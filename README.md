# 打击乐节奏创作工具

用户为每个声部指定**密度、重音位置（软/锁定）、最短间隔**，以及**跨声部呼应/互斥/齐奏**关系；
内核生成满足全部硬性条件的击打分布，再按**切分程度 + 重复结构**排列候选，合成真实音频试听。

并支持**保留主型的变奏与填充**：在指定小节内调整击打，硬保留用户锁定的节奏骨架、
关键重音与进入下一乐句的落点，区外事件原样不动；变奏距离按事件增删/位移/力度四维度预算约束，
末拍占用预算与跨边界实际毫秒间隔双重核验收束。

## 启动界面（主入口）

```bash
cd /workspace
python3 -m percussion_kernel.server          # 默认 8000 端口
# 或指定端口： python3 -m percussion_kernel.server --port 9000
```

然后浏览器打开 **http://localhost:8000** 。界面控件（声部表、重音条、关系、全局参数）
全部由打击乐内核的默认配置/目录驱动；求解失败（不可满足）会把**最小锁定集合**反馈回界面并高亮涉及声部。

**变奏/填充的图形入口**：先在「结果」候选卡片点 **作为变奏原型**，页面下方出现
「保留主型的变奏与填充」面板——选择变奏小节、参与声部、变奏距离上下限、末拍占用预算与乐句落点，
点 **生成变奏（两种策略对照）**。面板逐项显示每个变化是否在允许范围，并对接受/舍弃候选分别提供
**试听**与**试听原型对照**（均调用内核实时渲染，无固定数据冒充）。

仅依赖 Python 3 标准库，无需安装任何第三方包。

## 命令行（仅辅助）

无界面环境下可用 CLI 快速核验并渲染 WAV（输出到 `out/cli/`）；主入口仍是上面的图形界面：

```bash
# 从约束生成，并把候选事件存为 JSON（可作为变奏原型）
python3 -m percussion_kernel.cli generate --seed 7 --json-out proto.json
# 对原型做保留主型的变奏（joint / staged 两种策略）
python3 -m percussion_kernel.cli variate --prototype proto.json \
  --variation '{"bars":[1],"voices":["kick","snare","hat_closed"],"min_distance":2,"max_distance":10,"fill_end_budget":2,"landing":[{"voice":"kick","step":16}]}' \
  --strategy joint --json-out variant.json
```

## 运行测试

```bash
python3 -m unittest discover -s tests -v
```

覆盖：过高密度不可解、互斥重音不可解（含最小锁定集合极小性抽查）、可行稀疏节奏端到端、
双手组自由击打回退、摇摆后实际时间终检、同种子可复算；以及**节奏变奏回归**（`tests/test_variation.py`）：

- **全部骨架锁定**：锁定重音/关键软重音/乐句落点在接受候选中零丢失，区外事件原样保留；
- **极短填充区**（每小节 4 步）与**多个连续变奏**：变化预算、可演奏性、骨架辨识事件保持；
- **变奏距离四维度**（新增/删除/位移步量/力度变化）：照抄原型（含纯力度）被拒绝，超上限改成另一套节奏也被拒绝；
- **末拍占用预算**：零预算下末拍窗口击打全部舍弃并给出原因；
- **跨小节填充核验硬约束**：跨边界的两次击打按实际毫秒复检最短间隔（含乐句循环包裹），
  构造性紧边界用例必须报出违规；
- **策略对照**：「先锁强拍再配填充（staged）」与「约束搜索同时决定变奏与收束（joint）」
  在同一候选空间上比较，等距候选中接不上下句的那个带原因进入舍弃列表，且舍弃候选仍可试听核对。

## 内核流水线（`percussion_kernel/`）

1. **欧几里得播种**（`euclid.py`）：Bjorklund 均匀分布作为各声部模式起点，而非随机节奏叠加。
2. **构造式修复**（`solver.py: constructive`）：锁定重音先落位，自由击打按欧几里得模板引导填充；
   **固定强拍与双手最短间隔互斥时，回退最近一次自由击打**（tabu 防循环），锁定重音绝不动。
3. **DFS 搜索**（`solver.py: search`）：跨声部关系（互斥/齐奏/呼应）与双手组间隔逐层检查，
   单声部可行性用精确 DP 判定（`voice_feasible`），密度/间隔不足会精确报出而非猜测。
4. **最小锁定集合**（`solver.py: minimal_core`）：求解失败时做删除式极小化，
   返回必然冲突的最小约束子集（锁定重音/密度/间隔/关系/双手规则），**绝不静默降低要求**。
5. **排序**（`rank.py`）：切分度（弱位击打 + 强位空置）与重复结构（跨小节动机复现）加权排列，
   附多样性筛选，候选之间差异可在界面与基准对比（绿=此候选独有，红虚=基准独有）。
6. **力度与微小时移**（`timing.py`）：力度抖动、摇摆、时移抖动全部受上限控制；
   时移上限自动收紧到步长一半以内。**最终检查以实际演奏时间（毫秒）为准**：
   原本禁止重叠的击打在加入摇摆后不得塌缩/次序颠倒，互斥关系按毫秒复检，冲突先回缩时移再上报。
7. **音频合成**（`synth.py`）：纯 Python 合成 kick/snare/hat/tom 等，输出混音与各声部分轨 WAV。
8. **保留主型的变奏与填充**（`variation.py`）：
   - 骨架 = 锁定重音 + 关键软重音（可选）+ 显式乐句落点，区外事件固定，保证前后乐句连接；
   - 变奏距离 = 新增 + 删除 + 位移（贪心配对按步量计）+ 力度变化，总距离落在 `[min, max]` 预算内；
   - **staged**：骨架先落位再随机配填充，末拍预算/落点/跨边界间隔留到叶节点检查（顺序相关、有舍弃）；
   - **joint**：最约束声部优先的 DFS，末拍预算逐层剪枝、收束与变奏同决，可在 staged 失败处找回可衔接解；
   - 每个候选过 `timing.validate_actual` 实际时间终检，`boundary_actual_check` 再核验跨边界毫秒间隔；
   - 接受与舍弃候选都带完整事件表与原因，舍弃不是静默丢弃，而是可试听、可解释。

## 界面功能

- 三个演示预设：**可行稀疏节奏**、**过高密度（不可解）**、**互斥重音（不可解）**。
- 候选卡片：车道图（力度=柱高，时移=水平偏移，锁定=金框）、分数、约束解释、
  修复回退记录、终检修正记录、打击事件与实际演奏时间表、播放/声部开关、**作为变奏原型**。
- 变奏面板：骨架芯片（金=锁定、蓝=关键重音、绿=落点）、两策略对照、逐项变化允许/越界标记、
  末拍预算与跨边界毫秒核验、接受与舍弃候选分别试听并与原型对照。
- 编辑器：点击增删击打（锁定不可删）、力度滑杆、实时硬约束校验、试听编辑结果。
- 保存版本：种子 + 规则 + 所选版本存为 JSON（服务器 `sessions/` + 本地下载），
  载入后按种子复算并恢复所选版本与编辑。

## API

| 路径 | 说明 |
| --- | --- |
| `GET /api/default` | 默认配置、声部目录、三个预设 |
| `POST /api/generate` | 求解；`status: ok/unsat/budget`，失败含 `core` 最小锁定集合 |
| `POST /api/variate` | 保留主型的变奏/填充；返回两策略的接受/舍弃候选、四维度距离、末拍预算与跨边界核验 |
| `POST /api/audition` | 渲染 WAV，返回混音/分轨 URL 与实际演奏时间事件表（接受与舍弃候选同一入口） |
| `POST /api/validate` | 编辑结果的硬约束 + 实际时间校验 |
| `POST /api/save` / `GET /api/load?id=` | 存档与复算 |
